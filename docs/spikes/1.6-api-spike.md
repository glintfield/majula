# 1.6 API spike: findings

Roadmap job 1.6 tested Protobuf + Connect RPC with a TypeScript server and TypeScript, Swift and
Kotlin clients. The code in `spike/` is throwaway and a later job deletes it, so this doc is the
durable record. Until then, `spike/apple/README.md` and `spike/android/README.md` hold more detail.

## Verdict

Protobuf + Connect is confirmed; see [ADR 0003](../adr/0003-api-schema.md). All three clients pass
against the spike server: TypeScript 6/6, Swift 13/13 and Kotlin 8/8.

What this doesn't prove yet:

- The TypeScript server and client ran on Node 25.9, not Node 22, the platform target.
- Swift ran on macOS and the iOS simulator, and Kotlin on an emulator. No physical iPhone or
  Android device.
- Kotlin ran on API 35 only. minSdk 29 wasn't checked.
- Bidi streaming wasn't tested.
- Only a private CA was tested as the trust root. A raw pinned server key wasn't.
- Revoking a token doesn't end an open stream.

Each is in [Gaps and follow-ups](#gaps-and-follow-ups) with the job that owns it.

## What was tested

The server:

- Connect on `node:http2` `createSecureServer`, with `allowHTTP1` on.
- `Echo`, a unary call that returns its message.
- `Watch`, a server stream over one shared buffered event log. It emits an event per interval, 1 s
  by default and faster in the tests. `after_seq` replays buffered events and then continues live.
  It returns `failed_precondition` when the gap has left the buffer and `out_of_range` when
  `after_seq` is ahead of the log.
- A bearer-token interceptor on both RPCs.
- A one-day leaf signed by a long-lived private CA, with SANs `localhost`, `127.0.0.1` and
  `10.0.2.2`, reloaded on `SIGHUP` without a restart.

| Scenario                          | TS         | Swift      | Kotlin |
| --------------------------------- | ---------- | ---------- | ------ |
| Unary call                        | pass       | pass       | pass   |
| Missing or wrong token            | pass       | pass       | pass   |
| Server stream                     | pass       | pass       | pass   |
| Resume with `after_seq`           | pass       | pass       | pass   |
| Rotated leaf                      | pass       | pass       | pass   |
| Unknown CA rejected               | not tested | pass       | pass   |
| Resume after backgrounding        | n/a        | pass       | pass   |
| Un-cancelled stream in background | n/a        | not tested | pass   |

Swift and Kotlin assert that the unary call negotiated HTTP/2, because the server also accepts
HTTP/1.1 and a silent downgrade would otherwise pass. The TypeScript client is configured for
HTTP/2 but doesn't assert it.

| Client | Libraries and platform                                                                   | Result |
| ------ | ---------------------------------------------------------------------------------------- | ------ |
| TS     | connect-node 2.x on Node 25.9, vitest                                                    | 6/6    |
| Swift  | connect-swift 1.2.3, swift-protobuf 1.41.0, Xcode 27.2; macOS 26.6.2, iOS 27.0 simulator | 13/13  |
| Kotlin | connect-kotlin 0.10.0, OkHttp 5.5.0, Kotlin 2.4.21; Pixel 6 emulator, API 35, arm64      | 8/8    |

Swift's 13 are six tests on macOS, the same six on the iPhone 17 simulator, and one backgrounding UI
test. Its deployment target is iOS 17. Kotlin's 8 are the same six plus two backgrounding tests,
with minSdk 29, targetSdk 35 and compileSdk 37. The harnesses are `npm --prefix spike test`,
`spike/apple/scripts/test.sh` and `spike/android/scripts/test.sh`.

## Findings

### Transport: unary and server-streaming over HTTP/2

- Both work on URLSession and on OkHttp. Connect-Swift didn't need NIO.
- Frames arrive incrementally. Swift's stream test never sees the stream end, so it can only pass
  if events are delivered as sent; five events at 100 ms took about 0.47 s.
- connect-kotlin's default `timeoutOracle` gives every call a 10 s deadline, streams included. A
  long-lived stream needs `simpleTimeouts(unaryTimeout, streamTimeout = null)`, or it ends at 10 s.
- Bidi wasn't tested, and the proto has none. The spike's Swift transport buffers the request body
  until close, so it can't do bidi; URLSession's own limit is unprobed.

### Auth headers

- TypeScript adds the bearer token with a Connect interceptor and Swift with
  `BearerAuthInterceptor`, also a Connect interceptor. Kotlin uses an OkHttp interceptor instead.
- The server rejects a missing or wrong token with `unauthenticated`, on both the unary call and
  the stream.
- The server checks the token only when a call starts. Revoking it wouldn't end an open `Watch`,
  and threat-model invariant I10 requires that revocation reaches open streams. Not tested.

### Custom trust root

Both clients anchor trust on the private CA alone and never pin the leaf.

- **Swift:** `SecTrustSetAnchorCertificates([ca])`, then `SecTrustSetAnchorCertificatesOnly(true)`,
  then `SecTrustEvaluateWithError`. Apple's chain, expiry, hostname and EKU checks all still run.
- **connect-swift can't take a trust root.** `URLSessionHTTPClient` is `open`, but its URLSession
  delegate is a private wrapper that never forwards `urlSession(_:didReceive:completionHandler:)`,
  so a subclass's challenge handler is never called. The spike carries its own
  `HTTPClientInterface`, `AnchoredHTTPClient`, at about 260 lines. `NIOHTTPClient` does have an
  `open createTLSConfiguration(forHost:)` hook.
- **Kotlin:** `ConnectOkHttpClient` takes any `OkHttpClient`. The spike builds one from okhttp-tls
  `HandshakeCertificates.Builder().addTrustedCertificate(ca)` with no platform roots, in about 10
  lines. OkHttp's chain, expiry and hostname checks still run.
- **An SPKI pin alone was rejected on both, for different reasons.** On Kotlin, a pin only filters
  chains that trust has already accepted, and platform trust rejects the private CA. On Swift, it
  means walking the chain by hand and still running an evaluation. Either could add one on top as
  defence in depth.
- **Leaf rotation is invisible to clients.** The Swift and Kotlin harnesses rotate the leaf before
  the clients run; the TypeScript test rotates it mid-suite, then makes a new call. Each asserts the
  served leaf's fingerprint changed and the call still succeeds. No test holds a connection open
  across a rotation; an open HTTP/2 connection is expected to keep the leaf it handshook with.
- **An unknown CA is rejected,** with no response and exactly one recorded rejection. Neither test
  asserts the Connect code. Swift's is inferred to be `.canceled` from how the transport maps a
  cancelled challenge, and Kotlin logged `UNKNOWN` wrapping `CertPathValidatorException`. Neither is
  distinguishable by code from a user cancel or an I/O error, so a real client needs its own
  rejection signal, like the spike's `TrustObserver`.
- The IP SAN `10.0.2.2` matched on Android with no extra configuration.

### ATS and Android network security config

- **App Transport Security needed no exceptions.** The leaf is ECDSA P-256 signed with SHA-256. The
  negotiated TLS version wasn't recorded.
- Apple's rules for TLS server certificates, checked against Apple's docs rather than tested: names
  in the SAN, the `serverAuth` EKU, SHA-2 signatures, and validity of at most 825 days. The 398-day
  cap applies only to certificates that chain to Apple's trust store, so it binds neither the
  private CA nor its leaves. The leaves must still stay within 825 days.
- **Android needed no `network_security_config`.** It governs the platform's default trust manager
  and cleartext policy. OkHttp with its own `X509TrustManager` bypasses the first, and every call is
  HTTPS. The manifest needs only `INTERNET`.

### Reconnect after backgrounding

- Both apps cancel the stream when backgrounded and restart it on return, passing `after_seq` set to
  the last seq received. Swift does it on `scenePhase`, Kotlin with `repeatOnLifecycle(STARTED)`.
- Both tests stream, go to the home screen for 5 s and come back. They assert at least two
  connects, `lastSeq` advanced at least 40 into the roughly 50 events emitted while away, and zero
  gaps or duplicates. A reconnect without `after_seq` would start at the live head and count a gap,
  so this proves replay.
- On Android, an un-cancelled stream kept running for 15 s while the activity was stopped: 148 and
  149 events arrived on the same connection in two runs. That doesn't predict a shipped app. The
  instrumentation process isn't frozen like an ordinary backgrounded app, and 15 s reaches neither
  Doze nor App Standby.
- On iOS, what happens to an un-cancelled stream wasn't measured.
- Swift's `ResumableWatch` also retries in the foreground, backing off from 250 ms to 5 s and
  stopping on terminal codes. Kotlin's doesn't, so a dropped network leaves the stream dead until
  the next `onStart`.

### Codegen

- buf CLI with v2 config, installed from npm as `@bufbuild/buf`, not protoc.
- One template per target, so regenerating one language needs no other language's plugins:
  - `buf.gen.yaml`: TypeScript with the local `protoc-gen-es` plugin.
  - `buf.gen.swift.yaml`: BSR remote plugins `buf.build/apple/swift:v1.41.0` and
    `buf.build/connectrpc/swift:v1.2.3`.
  - `buf.gen.kotlin.yaml`: BSR remote plugins `buf.build/protocolbuffers/java:v36.2` (`lite`) and
    `buf.build/connectrpc/kotlin:v0.10.0`.
- The BSR remote plugins were reachable with no login.
- Generated code is committed for all three targets.
- Swift's generated code compiles in Swift 6 language mode with strict concurrency.

### Build and machine friction

- `xcode-select` pointed at the Command Line Tools, which have no XCTest and no simulators, so the
  harness sets `DEVELOPER_DIR`. The first simulator run also needed a one-time
  `sudo xcodebuild -runFirstLaunch`.
- A SwiftPM package carries the client and its tests, and one test target runs on macOS and iOS.
  Only the app and its UI test need an `.xcodeproj`. It's hand-written, about 330 lines with
  synchronized folders, and signs with `CODE_SIGN_IDENTITY = "-"` and no team.
- With no system `gradle`, the wrapper was bootstrapped from the official distribution, checked
  against its SHA-256. `gradle-wrapper.properties` pins `distributionSha256Sum`.
- AGP 9 bundles KGP 2.2.10, so `org.jetbrains.kotlin.android` 2.4.21 is pinned to match
  connect-kotlin 0.10.0.
- okhttp-android 5.5.0 requires compileSdk 37.
- The emulator boots headless from a script in about 30 s.
- The machine has Node 25, not 22.
